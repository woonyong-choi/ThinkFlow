# 계열 색 순서·작은 글자·축선을 Things와 실서비스 도구의 균형으로 정한다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-16 |
| 상태 | 채택 |
| 대체 | 핵심 네 색(파랑, 노랑, 빨강, 초록)의 순서를 고정하던 규칙 |
| 관련 문서 | [차트](../design/charts.md), [문서 통합](../design/docs-integration.md), design-tokens `docs/styles.md` |

## 배경

실서비스 도구(Mermaid, Vega-Lite, D2, PlantUML 등)와 같은 예제를 지표로 비교했다. 글자 겹침·잘림·글자 대비는 같거나 나았고, 다음 셋은 ThinkFlow 규칙 때문에 뒤졌다.

- 계열 색 순서가 파랑, 노랑, 빨강이었다. 둘째 노랑은 흰 면 위 대비가 낮고, 셋째 빨강은 오류·손실로 읽혔다. 색각 이상 모의에서 빨강·초록 이웃 쌍의 거리가 7.1로 가장 가까웠다.
- 작은 표시 글자가 11px였다. Vega-Lite는 10~11px, Mermaid는 16px다.
- 차트 축선이 격자와 같은 옅은 색이라 값을 재는 기준선이 차트 면 위 3:1에 못 미쳤다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 기존 규칙 유지 | 바꿀 것이 없다 | 위 세 가지가 남는다 |
| 실서비스 도구 기본값을 그대로 따른다(Tableau 10 색, 14~16px 글자, 진한 테두리) | 비교 지표가 모두 맞는다 | Things의 옅은 윤곽과 차분한 위계가 사라진다 |
| 역할마다 균형을 고른다 | 읽는 데 필요한 것만 도구 수준으로 올리고 나머지는 Things를 지킨다 | 판단 근거를 기록해야 한다 |

## 결정

역할마다 균형을 고른다. 사용자가 이 방식을 채택했다.

- 계열 순서: blue, orange, cyan, yellow, green, purple, red. 첫 두 색은 색각 이상에서도 가장 잘 갈리는 파랑·주황이다. 빨강은 맨 뒤다. 가운데 순서는 앞 네 색의 모든 쌍, 이웃 쌍, 같은 점 모양 쌍의 OKLab 거리를 정상·제1·제2색각 모의(Machado 2009)로 재어 가장 가까운 쌍이 가장 먼 순서다(최소 7.1에서 11.5).
- 라이트 계열 면색은 Things 기준색과 이전 차분한 값의 중간이다. 다크는 그대로다.
- 작은 표시 글자는 12px다. 카드 제목 15px, 문장 13px은 그대로다.
- 카드·그룹 윤곽과 차트 격자는 Things처럼 옅게 둔다. 카드는 면과 그림자가 구분한다. 차트 축선만 관계선 색으로 진하게 한다.
- 이동 글 상자는 색 이름과 상관없이 진한 흐름 면에 흰 글자다. 차트 면색 위 글자가 흰색·검정으로 섞여 보이던 문제를 없앤다.

## 결과

- 원본에 색 이름을 쓰지 않은 점, 태그, 차트 계열의 색이 바뀐다. 색 이름(`tone=blue` 등)을 쓴 원본은 그대로다.
- 그림 전체를 다시 만든다. 작은 글자가 커져 배치 크기가 조금 바뀐다.
- 순서를 다시 바꿀 때도 결정 기록을 남긴다.
