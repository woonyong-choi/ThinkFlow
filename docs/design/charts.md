# 차트

| 항목 | 값 |
|---|---|
| 상태 | 구현 |
| 관련 결정 | [그림 문법과 배치를 직접 맡고 D2 호환을 버린다](../decisions/2026-10-01-own-syntax-and-layout.md) |

## 요약

차트는 첫 문장이 `chart {종류}`인 원본으로 숫자를 그리는 기능이다. 막대, 덤벨, 상자, 산점도, 선, 히트맵 여섯 종류를 그리고, 흐름 그림과 같은 단계와 박자로 계열을 차례로 드러낸다. 값은 원본에 적거나 실험 결과 JSON에서 읽는다.

## 동기

문서 스킬은 구조 그림을 D2로, 실험 차트를 Vega-Lite로 그린다. 두 도구는 글꼴, 색, 여백, 움직임이 달라서 한 문서 안의 그림이 두 모양이 된다. 차트도 같은 문법, 같은 토큰, 같은 재생기로 그리면 문서 전체가 한 모양이 되고, 구조 그림처럼 "기준선을 보인 뒤 우리 값이 자라는" 순서를 보일 수 있다.

## 예시

### 기준선에서 개선 값으로 자라는 덤벨

```text
chart dumbbell
title "작업당 토큰"
subtitle "예시 데이터. 에이전트마다 작업 61개 평균"
x "토큰(로그 눈금)"
scale log

series base "기억 없음" role=compare
series ours "기억 붙임" role=main

row "코딩 에이전트 A" base=120000 ours=31000
row "코딩 에이전트 B" base=95000 ours=28000

step "기억 없음" "기억 없이 쓴 토큰이다"
  reveal base
step "기억 붙임" "같은 작업에서 기억을 붙이면 토큰이 준다"
  reveal ours
  light "코딩 에이전트 A"
  say "에이전트 A는 74% 줄었다"
```

1. 첫 단계에 `base` 점만 보인다.
2. 둘째 단계에서 점마다 `ours` 값까지 화살표가 자라고, 오른쪽에 `−74%`가 나타난다.
3. `light` 박자에 첫 행이 밝아지고 둘째 행이 흐려진다.

### 실험 결과에서 읽는 막대

```text
chart bar
title "조건별 오분류율"
subtitle "n=500. 점선은 채택 기준 5%"
x "오분류율(%)"

data "../summary.json" at "/misclassification"
series ours "새 판단기" key="new_judge"
rule 5 "채택 기준"
```

1. `summary.json`의 `/misclassification` 배열이 행이 된다. 원소 키 `new_judge`가 계열 `ours`의 값이다.
2. 행마다 막대와 신뢰구간 막대기(끝 캡이 없는 선), 5% 점선이 그려진다.

## 상세 설계

### 종류와 행 줄

| 첫 문장 | 보여 줄 것 | 계열 수 | 행 줄 |
|---|---|---|---|
| `chart bar` | 조건별 값과 신뢰구간 | 1~2 | `row "항목" 계열=값`, 계열마다. 신뢰구간은 `계열.low=값 계열.high=값` |
| `chart dumbbell` | 같은 입력에서 두 방식 비교 | 정확히 2 | `row "항목" 계열=값 계열=값`. 신뢰구간은 막대와 같다 |
| `chart box` | 연속값 분포 | 0 | `row "항목" min=값 q1=값 median=값 q3=값 max=값` |
| `chart scatter` | 두 변수의 관계 | 0~2 | `point "이름" x=값 y=값`, 계열이 있으면 `series=계열`도. `link "이름" -> "이름"` |
| `chart line` | 순서나 시간에 따른 변화 | 1~2 | `point x=값 계열=값`, 계열이 둘이면 두 계열 값 모두. 신뢰구간은 `계열.low=값 계열.high=값` |
| `chart heatmap` | 판정 교차표 | 0 | `cell "행" "열" 값` |

- 표의 여섯 종류는 문서 스킬의 Vega-Lite 차트 표와 일대일이다.
- 계열 수가 표를 벗어나면 오류다. 문서 스킬이 셋 이상의 계열을 차트를 나누게 하기 때문이다.
- 산점도에 계열을 선언하면 모든 점에 `series=`가 필요하다.
- 신뢰구간은 막대, 덤벨, 선 차트가 받는다. 산점도는 받지 않는다. 점 하나의 두 값(비용과 수정 횟수)과 `link` 화살표가 이미 있어, 오차 막대가 겹치면 어느 점의 구간인지 헷갈리기 때문이다. 값마다 `low`와 `high`를 함께 적고(`계열.low`, `계열.high`), `low ≤ 값 ≤ high`다. 같은 값은 허용한다. 반올림한 실험 값에서 끝이 값과 같아질 수 있기 때문이다. 빠진 값에는 신뢰구간을 적을 수 없다. 둘 다 적거나 둘 다 생략하는 규칙은 세 종류가 같고, 행마다 따로 정한다. 선 차트의 띠는 신뢰구간이 연속으로 있는 점 사이에만 그려진다. 신뢰구간이 없는 점에서 띠가 끊기므로, 선 끝까지 띠가 있으려면 모든 점에 신뢰구간을 적는다.
- 상자 그림 값은 `min ≤ q1 ≤ median ≤ q3 ≤ max`다. 어기면 수염과 상자가 거꾸로 그려지므로 오류다.
- 산점도의 `link`는 앞 점에서 뒤 점으로 화살표를 긋는다. 같은 대상의 이전과 이후를 보이기 위해서다. 두 점이 모두 보일 때 보인다. 없는 점 이름을 가리키거나, 한 점을 자기 자신과 잇거나, 같은 `link`를 두 번 적으면 오류다.
- 항목, 이름, 행과 열의 짝, 선 차트의 `x` 값은 차트 안에서 하나다. 겹치면 오류다. `light`가 가리킬 대상이 하나여야 하기 때문이다.
- 막대와 상자, 덤벨은 가로로 그린다. 항목 이름이 길어도 줄이지 않기 위해서다. 이름 칸은 가장 긴 이름에 맞춰 토큰 `size.chart.label`에서 `size.chart.label-max`까지 넓어진다. 그보다 긴 이름은 [그림 검사](figure-check.md) 1번 오류다.

### 머리와 선언 줄

| 줄 | 부분 | 뜻 |
|---|---|---|
| `title "글"`, `subtitle "글"` | 머리 | 제목과 부제. 부제는 표본 수와 기준선 설명(문서 스킬 규칙) |
| `x "축 제목"`, `y "축 제목"` | 머리 | 축 제목. 단위는 괄호에 넣는다 |
| `scale linear\|log` | 머리 | 값 축 눈금. 기본 `linear` |
| `decimals 0~6` | 머리 | 값 글자(막대, 덤벨, 상자, 히트맵)의 소수 자릿수. 기본은 같은 목록에 적힌 가장 긴 소수 자릿수 |
| `speed 900ms` | 머리 | `reveal`로 계열이 자라는 시간. 기본 토큰 `duration.reveal` |
| `series id "이름" [role=main\|compare] [key="JSON 키"]` | 선언 | 계열과 역할. 계열이 하나면 main이라 `role`을 생략할 수 있고(`role=compare`는 오류), 둘이면 main 하나, compare 하나다. `role`을 생략하면 선언 순서대로 첫 계열 main, 둘째 compare를 받고(덤벨은 시작점이 compare라 첫 계열 compare), 하나만 적으면 다른 계열이 남은 역할을 받는다([호환 규칙](figure-syntax.md#호환-규칙)). 적은 역할이 있으면 색은 역할이 정하고 선언 순서와 상관없다([색 역할 표](docs-integration.md#색-역할)). 범례, 막대, 점 이름 칸은 main이 먼저다 |
| `rule 값 "라벨"` | 선언 | 기준선. 여러 줄 가능. 보조 글자 색 점선 |
| `missing "글"` | 선언 | 막대 값이 빠진 자리 글. 기본 `비교 없음` |
| `data "경로" [at "/포인터"]` | 선언 | JSON 파일의 배열에서 행을 읽는다. `at`을 빼면 문서 전체가 배열이다 |
| 행 줄 | 선언 | 종류와 행 줄 표 |

- 축 제목 `x`, `y`는 아래 값 축 표의 가로축, 세로축 제목이다.
- 값 축(아래 표의 값 축 칸)의 제목이 없거나 괄호 단위 `(…)`가 없으면 경고다. 막대, 덤벨, 상자는 `x`, 선은 `y`, 산점도는 `x`와 `y`가 대상이고 히트맵은 값 축이 없어 대상이 아니다. 단위 없는 숫자는 읽는 사람이 값을 해석할 수 없기 때문이다. 메시지는 `the value axis title needs a unit in parentheses, such as x "latency(ms)"`이고, 경고라 `--strict`에서 실패한다.

| 종류 | 가로축 | 세로축 | 값 축(`scale`, `rule`, 0 시작이 걸리는 축) | 음수 |
|---|---|---|---|---|
| `bar`, `dumbbell`, `box` | 값 | 항목 | 가로축 | 오류 |
| `line` | `x` 값 | 계열 값 | 세로축 | 쓸 수 있다 |
| `scatter` | `x` 값 | `y` 값 | 두 축 모두 | 쓸 수 있다 |
| `heatmap` | 열 | 행 | 없음. `scale`, `rule`은 오류 | 오류 |

- 막대에서 `scale log`와 음수 기준선은 오류다. 문서 스킬이 막대 축을 0에서 시작하게 하기 때문이다.
- `scale linear`의 값 축은 0과 가장 작은 값 가운데 작은 쪽에서 시작한다. `scale log`의 값 축은 가장 작은 값 이하의 10의 거듭제곱에서 시작한다. `scale log`에서 값 축의 0 이하 값과 0 이하 기준선은 오류다. 막대, 덤벨, 상자에서 값이 모두 0이면 오류다. 길이로 값을 보이는 차트라 그릴 것이 없기 때문이다. 선 차트와 산점도는 위치로 보이므로 모두 0이어도 그리고, 눈금은 0에서 1이다.
- 선언한 계열마다 행 줄에 값이 하나씩 있어야 한다. 값이 없으면 빠진 값 `-`를 적는다. 빠진 값 `-`는 막대 계열 값에만 쓴다. 그 밖의 자리에서는 오류다.

### 값 출처

- `data`와 `row`, `point`, `cell`을 함께 쓰면 오류다. 값의 출처가 하나여야 하기 때문이다. `link`는 `data`와 함께 쓸 수 있다.
- `data` 경로는 원본 파일 기준 상대 경로이고, `at`은 JSON Pointer(RFC 6901)다. 포인터는 `/`로 시작하고, `"/"`는 빈 이름 키를 가리킨다. 가리킨 값은 배열이어야 한다.
- 계열 값은 원소의 키 `key=`에서 읽고, `key=`가 없으면 계열 이름과 같은 키에서 읽는다. 신뢰구간은 `{키}.low`, `{키}.high` 키다. 계열 키가 그 종류의 고정 원소 키(`label`, `name`, `x`, `y`, `series`, `row`, `col`, `value`)와 같으면 오류다.
- 산점도 원소의 `series` 값은 계열의 키(`key=`, 없으면 계열 이름)와 맞춘다.
- 값은 숫자나 `null`(빠진 값)이다. 문자열, 불리언, 객체, 배열은 오류다. 이름 키(`label`, `name`, `row`, `col`)는 글이어야 하고, 빠지면 오류다.
- 값의 절댓값은 `1e15` 미만이다. 그보다 크면 12자리 십진 반올림으로 눈금과 글자를 정확히 쓸 수 없기 때문이다.
- 빠진 값은 JSON `null`이거나 키가 없는 것이다. 둘은 같다. 막대 계열 값 밖의 빠진 값은 오류다.

| 종류 | 원소 키 |
|---|---|
| `bar` | `label`, 계열 키, `{계열 키}.low`, `{계열 키}.high` |
| `dumbbell` | `label`, 계열 키 둘, 계열 키마다 `.low`, `.high` |
| `box` | `label`, `min`, `q1`, `median`, `q3`, `max` |
| `scatter` | `name`, `x`, `y`, `series` |
| `line` | `x`, 계열 키, 계열 키마다 `.low`, `.high` |
| `heatmap` | `row`, `col`, `value` |

- 표에 없는 키가 있으면 경고다. 키 이름 오타를 알리기 위해서다.

### 시간 흐름

| 줄 | 뜻 |
|---|---|
| `step "이름" ["설명"]` | 단계 |
| `reveal 계열 [계열 ...]` | 계열을 드러낸다. 여럿을 적으면 함께 드러낸다. 막대와 상자는 값 축 시작에서 자라고, 덤벨 main 계열은 compare 값에서 화살표가 자라 끝점으로 닿고, 선 차트의 선은 왼쪽부터 그어진다. 점과 값 글자는 흐린 상태에서 나타난다 |
| `light "항목"` | 막대, 덤벨, 상자의 행이나 산점도의 점을 밝히고 나머지를 흐리게 한다 |
| `light x=값` | 선 차트에서 그 `x`의 점들을 밝힌다 |
| `light "행" "열"` | 히트맵 칸 하나를 밝힌다 |
| `say`, `wait` | [그림 문법](figure-syntax.md)과 같다 |

- 시간 흐름이 없거나 `reveal`이 하나도 없으면 모든 계열이 처음부터 보이고 첫 박자에 자란다. 계열이 없는 종류는 차트 전체를 계열 하나로 보고 첫 박자에 자란다.
- 자라는 시간은 `speed`이고 곡선은 토큰 `easing.reveal`이다. 막대, 상자, 선, 띠는 그 시간 내내 자라고, 값 글자는 뒤 절반에 나타난다. 선 차트의 점(과 한 점짜리 오차 막대)은 선이 그 점에 닿는 시각에 나타난다. 선은 길이 순서로 그려지므로 그 시각은 길이 비율을 `easing.reveal`의 시간 비율로 거꾸로 푼 값이고, 그리기 단계가 자라는 시간 대비 비율로 계산해 요소의 `data-at`에 담는다. 재생기와 움직이는 SVG는 자라는 시간을 곱해 걸기만 한다. HTML 재생기와 움직이는 SVG가 같다.
- 시간 흐름이 없는 차트는 토큰 `duration.chart-cycle`마다 같은 움직임으로 다시 자란다.
- `reveal`이 하나라도 있으면 드러내기 전의 계열은 숨는다. 끝까지 드러내지 않는 계열은 오류다. 보이지 않을 값을 적는 일을 막기 위해서다.
- 같은 계열을 두 번 드러내면 오류다.
- 덤벨에서 main 계열을 compare 계열보다 먼저 드러내면 오류다. 화살표의 시작점(compare)이 없기 때문이다.
- 범례는 계열을 드러내기 전에도 모두 보인다. 드러난 계열의 범례만 남으면 범례가 왼쪽이 빈 채 어긋나 보이기 때문이다.
- 범례, 막대, 점 이름 칸은 역할 차례(main 먼저)로 고정이고, 단계(탭)는 이야기 차례라 작성자가 정한다. 그래서 "기억 없음 → 기억 붙임" 같은 전 → 후 순서로 드러내도 된다. 덤벨만 화살표가 compare에서 시작하므로 compare를 먼저 드러낸다.
- 계열이 없는 종류(상자, 히트맵, 계열 없는 산점도)에서 `reveal`은 오류다.
- 드러낸 계열은 단계가 바뀌어도 남는다. 구조 그림과 다른 이유는 차트의 단계가 값을 쌓아 보이는 순서이기 때문이다. `light`는 그 단계 끝까지 남고 다음 단계에서 꺼진다. 같은 단계의 `light`는 앞의 것에 더해진다.

### 그리기

- 크기와 색은 토큰이다. 차트 너비는 `size.chart.width`(표준 캔버스 폭 `size.figure-canvas`와 같은 960)라 모든 차트가 다른 그림과 같은 폭으로 가로를 꽉 채운다. 이름 칸은 이름에 맞추고 남는 폭은 모두 그림 영역이다. 오른쪽에는 왼쪽 여백(이름과 제목이 시작하는 `28px`)과 같은 여백을 둔다. 가장 멀리 닿는 요소(막대와 상자의 값 글자, 덤벨의 바뀐 비율 글자, 눈금 글자, 기준선 라벨, 점)의 오른쪽 끝이 960에서 28을 뺀 자리에 놓이게 값 축 길이를 글자 폭(`measure`)으로 계산해 정하므로 내용이 판 가운데에 놓인다. 선 차트와 산점도에 제목, 범례, 세로축 제목이 모두 없으면 왼쪽 끝은 세로축 눈금 글자 왼쪽 끝이고 오른쪽 여백을 그만큼 둔다. 반 폭 같은 폭 선택 사항은 없다. 또한 행 높이, 막대 두께, 점 크기도 토큰이다. 점 크기는 값과 상관없이 같다(문서 스킬 규칙).
- 위아래 여백은 토큰 `space.14`(28px) 하나다. 위는 제목 글자 줄 윗면이 그림 윗면에서 `space.14` 아래에서 시작하고, 아래는 마지막 글자 줄(축 제목, 없으면 눈금 글자) 기준선 아래 `space.1-5`(기준선 아래로 내려오는 먹 몫)에 `space.14`를 더한 곳이 그림 아래 끝이다. 그래서 라이트 1400 캡처에서 제목 먹 위 여백과 축 제목 먹 아래 여백이 모든 종류에서 1px 안으로 같다(히트맵은 마지막 줄이 칸이라 칸 아래 끝에서 `space.14`). 값 축 아래 글자(눈금, 축 제목)는 막대, 덤벨, 상자, 산점도, 선이 같은 규칙과 같은 간격으로 놓는다.
- 흐림(`light`가 밝히지 않은 행)은 면과 글자를 따로 흐린다. 면(막대, 점, 띠, 히트맵 칸)은 불투명도 토큰 `opacity.dim`(0.3)이고, 글자(이름, 값, 점 이름, 칸 숫자)는 `ink` class 묶음으로 따로 담아 `opacity.dim-ink`(0.82)로 덜 흐린다. 면과 글자가 한 묶음이면 글자가 면과 같은 비율로 흐려 바탕과 구별이 안 되기 때문이다. 흐린 상태의 대비는 테스트가 잰다. 값 글자(`color.fg`), 보조 글자(`color.muted`), 히트맵 칸 숫자 모두 라이트와 다크에서 4.5 이상이다(흐린 보조 글자 라이트 4.68, 다크 4.81). 히트맵 칸은 면이 바탕 쪽으로 옅어지는 중간에 밝은 글자도 어두운 글자도 4.5에 못 미치므로, 흐림이 바뀔 때 면, 글자 불투명도, 글자색이 서서히 가지 않고 한꺼번에 바뀐다(움직이는 SVG와 재생기 모두). 테스트가 60fps 모든 프레임의 대비를 잰다.
- 히트맵 칸은 흐려지면 면이 바탕 쪽으로 옅어져, 진한 칸에 쓰던 밝은 글자가 옅은 면 위에서 묻힌다. 그래서 흐린 동안은 모든 칸 숫자가 `color.data.heat-ink`(라이트 어두운 글자, 다크는 같은 밝은 글자)로 바뀐다. 칸마다 평소 글자 색은 변수 `--ink`에 두고 흐릴 때 이 값만 바꾼다. 움직이는 SVG도 같은 값을 keyframes로 건다.
- 세로 값 축 기준선(산점도, 선 차트)의 라벨은 오른쪽 끝 기준선 위가 기본이다. 그 자리를 데이터(선, 띠, 점, 점 이름)가 가리면 왼쪽 끝으로 옮기고, 가린 수가 같으면 오른쪽에 둔다. 가로 값 축 기준선(막대, 덤벨, 상자)의 라벨은 행 위쪽 바깥이라 옮기지 않는다.
- 값 글자와 점 이름은 둘레에 바탕색 테두리를 둘러 뒤의 격자와 기준선이 글자 둘레에서 끊기게 한다.
- 값 글자는 막대 끝 바깥, 덤벨 화살표 양 끝 바깥에 둔다. 두 값이 가까워도 글자가 겹치지 않게 하기 위해서다. 값 글자는 둘레에 바탕색 테두리(토큰 `border.halo`)를 두고 기준선 위에 그린다. 막대 값 글자가 기준선과 겹쳐도 비키지 않고 다른 막대와 같은 간격으로 막대(오차 막대) 끝 옆에 두며, 글자 둘레의 바탕색 테두리가 그 부분의 점선을 가려 끊어 보이게 한다. 테두리는 `--color-bg`라 라이트(옅은 회색)와 다크 모두 그림 바탕색과 같다.
- 막대의 항목 이름은 계열이 모두 보일 때와 멈춘 SVG에서 그 항목 막대 묶음의 세로 가운데에 둔다. 값이 없는 계열(`-`)의 슬롯은 막대가 아니라 안내 글(`missing`)만 있어서 묶음에 넣지 않는다. 그래서 그 행의 이름은 하나뿐인 막대의 가운데에 놓이고 막대와 나란하다. 막대 값 글자는 막대의 세로 가운데에 맞춘다. 계열이 둘이고 한 계열만 드러난 단계에서는 이름이 보이는 막대의 가운데로 옮겨 막대와 나란하게 한다. 옮길 거리는 시간표가 박자마다 행마다 `labelShifts`(px, 행 순서 목록)로 미리 계산해 두고, HTML 재생기와 움직이는 SVG는 그 값을 그대로 적용한다. 값이 없는 슬롯이 있는 행은 막대가 보이는 동안 그 막대 가운데를 따르고, 안내 글만 보이는 단계(그 계열을 먼저 드러낼 때)에서만 안내 글 슬롯 가운데로 내려간다.
- 막대 신뢰구간은 막대 세로 가운데에서 `low`부터 `high`까지 긋는 선이다. 끝 캡은 없다. 막대보다 가벼운 보조 표시라 글자색(`color.fg`) 가는 선(`border.tag`)이고, 막대 위에 얹히는 부분이 막대 색에 묻히지 않게 선 둘레에 바탕색(`color.bg`) 테두리(`border.casing`)를 먼저 깐다. 선과 테두리의 대비가 라이트와 다크 모두 3 이상이라(그래픽 기준) 막대가 파랑이든 주황이든 선이 또렷하고, 막대 밖에서는 바탕 위 가는 선이다. 값 글자는 `high` 바깥에 둔다.
- 산점도는 신뢰구간이 없다. 점 이름과 `link`만 그린다. `link` 선은 보조 글자 색에 굵기 토큰 `border.strong`이고 끝이 둥글며, 화살촉은 선 굵기에 비례한다. 선이 가늘면 화질이 거칠어 보이기 때문이다.
- 상자 차트의 상자(q1~q3) 채움은 `color.node`(라이트 흰색)다. 회색 그림 바탕 위에서 상자가 떠 보이고 푸른 기운이 없다. 테두리는 main 색이다.
- 선 차트 신뢰구간은 계열 색의 옅은 띠(`opacity.band`)다. 선과 점은 띠 위에 그린다. 회색 그림 바탕 위에서 탁해 보이지 않을 만큼 색이 살고 두 계열 띠가 겹쳐도 읽히게 불투명도를 0.22로 둔다. 띠는 계열이 자랄 때 선을 따라 왼쪽부터 드러난다. 신뢰구간이 있는 점이 이어지지 않고 하나뿐이면 면이 안 되므로 세로 오차 막대(보조 글자 색, 굵기 `border.edge`, 끝 캡 `size.chart.cap`)로 그린다. 선은 `stroke-dashoffset`으로 그리고(`.draw`가 `stroke-dasharray: 1`을 가진다), 띠는 같은 시간 동안 왼쪽부터 `clip-path`로 드러난다. 둘이 같은 시간에 끝나서 끝 상태에서는 띠가 선 끝까지 맞는다.
- 덤벨 신뢰구간은 점 뒤에 같은 줄로 깔리는 옅은 둥근 막대기(`size.chart.range`, `opacity.range`)다. 점, 화살표, 값 글자보다 뒤 레이어이고, 값 글자는 두 점과 두 범위를 모두 덮는 구간의 바깥에 둬서 막대기, 점, 화살표와 겹치지 않는다.
- 덤벨 끝점은 거리와 상관없이 모든 행에서 같은 모양이다. 시작점은 compare 색 빈 점, 끝점은 main 색 채운 점(바탕색 테두리, 반지름 `size.chart.dot`)이고 둘 다 항상 그린다. 두 점을 잇는 화살표는 두 점 가장자리(점 반지름과 `space.1` 간격 밖) 사이가 토큰 `size.chart.arrow-min`(16px) 이상일 때만 그린다. 모자라면 화살표만 빼고 점은 그대로 둔다. 화살촉이 점에 가려지는 일을 막기 위해서다. 두 점이 점 지름보다 가까우면 채운 끝점이 빈 시작점 위에 겹쳐 그려져 시작점 테두리가 가장자리로 비친다. 모양이 행마다 다르면 한 행만 다른 뜻으로 읽히기 때문에 공간이 모자랄 때 줄이는 것은 연결선뿐이다. 기준선은 점선이고, 기준선 값은 값 축 범위에 넣는다. 기준선이 그림 밖에 그려지지 않게 하기 위해서다. 히트맵 칸 안에는 값을 적는다. 칸 너비는 이름 칸 오른쪽에서 내용의 오른쪽 끝(960에서 28을 뺀 자리)까지 남은 폭을 열 수로 나눈 값이고 상한이 없으며, 칸 높이는 `size.chart.cell`이다. 열이 적으면 칸이 가로로 길어져 정사각 비율에서 벗어난다. 그래도 정사각 칸을 가운데에 두지 않고 폭을 채우는 쪽을 골랐다. 이 문서의 "모든 차트가 960 폭을 꽉 채운다"를 지키고, 정사각 칸은 열이 셋일 때 내용이 판 폭의 3분의 1(300px)에 그쳐 왼쪽에 쏠렸던 모습으로 돌아가며, 가운데 배치는 다른 차트의 왼쪽 여백 28과 어긋나기 때문이다. 칸 색은 값 0의 `color.data.heat-low`에서 최댓값의 `color.data.heat-high`까지 sRGB로 보간한다. 라이트는 옅은 파랑(꾸밈 요소, [색 역할 표](docs-integration.md#색-역할))에서 진한 파랑으로, 다크는 바탕보다 조금 밝은 낮은 채도의 남청(`color.palette.blue.850`)에서 파랑(`color.palette.blue.600`)으로 가서 값이 클수록 밝아진다. 칸마다 강도(0~1, 소수 셋째 자리까지)를 `--s` 변수로 두고 CSS `color-mix`가 색 변수로 계산하므로 다크 모드의 `color.data.heat-low`를 따라가고, `color-mix`를 모르는 뷰어는 라이트 값으로 구운 `fill` 속성을 쓴다. 칸 안 값 글자는 칸마다 `color.data.heat-ink`(어두운 글자)와 `color.data.heat-ink-on`(밝은 글자) 가운데 칸 색과 대비가 큰 쪽을 빌드 때 고르고(`src/contrast.js`) 어느 칸에서나 4.5 이상이다. 칸 색과 글자색은 `--s`에 적는 강도 한 값에서 같은 함수(`heatLook`)로 정하고, 테스트가 강도 0~1을 0.01 단위로 훑어 평소(밝힘)와 흐림 상태 모두 4.5 이상인지 라이트와 다크로 잰다. 라이트는 큰 칸에 흰색, 작은 칸에 순검정이다. 다크는 두 글자가 같은 흰색이고, 칸 색 범위(`color.palette.blue.850`에서 `color.palette.blue.600`)가 흰 글자와 4.5 이상이 되게 정했다. 색을 고르는 계산은 라이트 값으로만 하므로 다크 범위를 바꾸면 이 조건을 테스트가 다시 잰다. 열 이름이 칸 너비를 넘으면 [그림 검사](figure-check.md) 1번 오류다. 산점도 점 이름은 점 오른쪽에 두고, 내용의 오른쪽 끝을 넘으면 점 왼쪽에 둔다. link 화살표의 끝은 점 가장자리에서 `space.2`만큼 바깥에서 시작해, 화살촉(굵기 곱 `size.arrow.head`)이 어느 점의 이름 글자 상자(`space.2` 여유 포함)와도 겹치지 않을 때까지 시작 점 쪽으로 더 당긴다. 어느 쪽에도 들어가지 않으면 1번 오류다. 선 차트는 점을 표시한다.
- 덤벨의 시작점은 compare 색 빈 점, 끝점은 main 색 채운 점이다. 범례는 main, compare 순이다. 범례 색과 같게 하기 위해서다. 값 글자와 바뀐 비율 글자는 계열과 상관없이 글자색(`color.fg`)이다. 계열 색(특히 라이트의 파랑, 주황)은 글자로 쓰면 대비가 4.5에 못 미쳐서 막대, 점, 띠로만 전한다. 강조 계열(main)의 값 글자는 굵기(semibold)로만 구분한다.
- 덤벨은 오른쪽에 바뀐 비율을 적는다. 비율은 `(둘째 / 첫째 − 1) × 100`을 정수로 반올림한 값이고(절반은 0에서 먼 쪽), 줄면 `−`, 늘면 `+`를 붙인다. 첫 값이 0이면 적지 않는다.
- 상태 색(성공 초록, 실패 빨강)은 쓰지 않는다. 판정은 글자로 적는다(문서 스킬 규칙).
- 눈금과 바뀐 비율 글자의 숫자는 1000 이상이면 `k`, 1000000 이상이면 `M`을 붙이고, 소수 한 자리로 반올림(절반은 0에서 먼 쪽)한 뒤 끝의 `.0`은 지운다(`120000`은 `120k`, `1250`은 `1.3k`). 반올림한 값이 `1000k`가 되면 `1M`으로 쓴다. 1000 미만은 가장 짧은 십진 표기로 쓴다(`0.012`, `91.4`).
- 값 글자(막대와 덤벨 계열 값, 상자 가운데 값, 히트맵 칸 숫자)는 같은 목록 안에서 소수 자릿수가 같다. 목록은 막대와 덤벨은 계열, 상자는 가운데 값 열, 히트맵은 모든 칸이다. 자릿수는 머리 줄 `decimals N`(0~6)이고, 없으면 그 목록에 적힌 가장 긴 소수 자릿수(최대 6)다. 그래서 `0.6`, `0.05`, `1`이 `0.60`, `0.05`, `1.00`으로, 한 계열의 `85`, `91.4`가 `85.0`, `91.4`로 쓰인다. 모두 정수면 소수점이 없다. 1000 이상 값은 위 `k`, `M` 표기다. `decimals`는 생략할 수 있고 생략하면 입력의 자릿수를 따른다(판 1에 추가한 낱말, 예전에는 `85`와 `91.4`를 섞어 썼다).
- 상자 가운데 값 글자는 `중앙 230`처럼 무엇의 값인지 붙여 쓴다. 글자가 수염 오른쪽 끝 옆에 있어 최댓값으로 읽혔기 때문이다.
- 반올림은 십진 계산으로 한다. 이진 부동소수점 오차로 `−70.5`가 `−70`이 되는 일을 막기 위해서다.

### 문서 스킬 강제 선택 사항

| 선택 사항 | 뜻 |
|---|---|
| `--require-data` | 행 줄을 쓰면 오류다. 부제가 `예시 데이터.`로 시작하는 차트는 제외 |
| `--require-ci` | 막대, 덤벨, 선 차트의 값에 `.low`, `.high`가 없으면 오류다. 산점도는 대상이 아니다 |

- 문서 스킬의 `render_figures`가 `docs/experiments/` 아래 차트에 두 선택 사항을 붙인다. "값 손 기재 금지"와 "비율에 신뢰구간"을 도구가 지키게 하기 위해서다.

## 단점

- Vega-Lite가 그리는 그 밖의 차트(누적 막대, 면적, 지도)는 그릴 수 없다.
- 실험 결과 JSON의 키를 원소 키 표에 맞춰야 한다.

## 대안

- Vega-Lite 유지: 구조 그림과 모양, 움직임이 두 벌이 되어 버렸다.
- 세로 막대: 항목 이름이 길면 기울이거나 줄여야 해서 버렸다.
