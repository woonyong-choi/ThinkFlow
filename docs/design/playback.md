# 재생

| 항목 | 값 |
|---|---|
| 상태 | 구현 |
| 관련 결정 | 없음 |

## 요약

재생은 흐름을 박자 순서로 보여 주는 기능이다. 결과는 두 가지다. HTML은 단계 탭, 일시정지, 배속, 전체 화면이 있는 재생기이고, SVG는 스크립트 없이 모든 단계를 이어 반복하는 이미지다.

## 동기

문서를 읽는 사람은 설명 글을 읽는 동안 그림이 기다려 주기를 바란다. 한 파일로 된 GIF는 멈출 수 없고 크며 글자가 흐리다. GitHub README는 스크립트를 막아 HTML 재생기를 넣을 수 없다. 그래서 문서 사이트에는 조작할 수 있는 HTML을, GitHub에는 스스로 움직이는 SVG를 쓴다.

## 예시

### HTML에서 한 단계 다시 보기

1. 사용자가 `hindsight.html`을 연다.
2. 재생기가 첫 단계의 박자를 순서대로 보이고 탭 아래 막대를 채운다.
3. 사용자가 `recall()` 탭을 누르면 그 단계의 첫 박자부터 다시 시작한다.
4. 사용자가 배속 버튼을 누르면 1×, 2×, 0.5× 순서로 속도가 바뀐다.

### README에 움직이는 그림 넣기

1. 사용자가 `hindsight.svg`를 README에 이미지로 넣는다.
2. GitHub는 스크립트 없이 모든 단계를 이어 반복한다.

## 상세 설계

### 박자 시간

박자 하나는 점이 선을 지나는 이동 시간 M과 도착 뒤 멈추는 시간 D로 이루어진다.

| 값 | 정하는 법 |
|---|---|
| 이동 시간 M | 박자의 `+{시간}`, 없으면 `speed`, 없으면 토큰 `duration.hop` |
| 멈추는 시간 D | 그 박자에서 설명이 바뀌면 글자 수 × `duration.dwell-per-char`, `duration.dwell` 이상 `duration.dwell-max` 이하. 바뀌지 않으면 `duration.dwell` |
| 단계 끝 | 마지막 박자의 D에 `duration.step-end` 추가 |

- 단계의 첫 박자는 단계 설명이 새로 보이므로 설명이 바뀐 박자로 친다.
- 마지막 단계의 마지막 박자 뒤에는 첫 단계의 첫 박자로 돌아간다.
- 시간 토큰 값은 예제를 보며 정했고, 읽는 속도 측정으로 확인하지 않았다. 값은 `src/tokens.json`에 있다.

### 박자 상태

| 상태 | 한 단계 안에서 | 단계가 바뀔 때 |
|---|---|---|
| 밝은 선 | 지나간 선 전부 | 초기화 |
| 밝은 도형 | 밝은 선의 양 끝, `light` 대상, 카드가 찬 도형 | 초기화 |
| 카드 내용 | 다음 `show` 전까지 유지. 점이 도착하는 도형의 카드는 도착할 때 바뀜 | 초기화 |
| 설명 | 마지막 `:` 설명이나 `say`, 없으면 단계 설명 | 새 단계 설명 |
| 조용한 선 | 밝은 선일 때만 보임 | 숨김 |

- `cli`가 박자마다 이 상태를 미리 계산해 결과 파일에 넣는다. HTML과 SVG가 같은 상태를 쓰게 하기 위해서다.

### HTML 재생기

- 점은 `path.getPointAtLength`로 선 위를 옮기고, 가운데가 느린 곡선으로 가속한다.
- 점을 만들면 같은 프레임에 선의 시작점에 놓는다. 첫 프레임에 그림 구석에 보이는 일을 막기 위해서다.
- 도형에 마우스를 올리면 그 도형에 닿은 선을 밝힌다.
- 스페이스 키는 일시정지, `Esc`는 전체 화면 닫기다.
- 전체 화면은 브라우저 전체 화면을 쓴다. 쓸 수 없으면 창을 덮는 모양으로 대신한다.
- 확대·축소와 끌어 옮기기는 전체 화면에서만 켠다. 문서 안에서는 그림 전체를 그대로 보이는 편이 읽기 쉽기 때문이다.
- 전체 화면에서는 휠, 확대·축소·전체 보기 단추, 끌기로 그림을 본다. 배율은 1배에서 `scale.zoom-max`배 사이다. 전체 화면을 끝내면 전체 보기로 돌아간다.
- 전체 화면 단추와 확대·축소 단추는 아이콘을 그림으로 그린다. 글자 기호는 글꼴마다 모양이 다르기 때문이다.
- 점의 글 상자가 그림 밖으로 나가면 옆으로 밀어 넣고, 위가 모자라면 점 아래로 내린다.
- `prefers-reduced-motion`이 켜져 있으면 멈춘 채로 시작한다.
- iframe 안에서는 테두리와 바깥 여백을 없애고, 본문 높이를 바깥 쪽에 알린다.
- 그림은 화면 높이를 넘지 않게 줄여 아래 조작 막대가 항상 보이게 한다.
- 설명이 하나도 없는 그림은 설명 줄을 숨긴다.
- 탭을 옮기면 지금 탭이 아닌 진행 막대를 모두 비운다.
- 조용한 선은 밝은 선이거나 마우스를 올린 도형에 닿을 때만 보인다.

### 움직이는 SVG

- 켜짐과 꺼짐 순서가 같은 요소끼리 CSS keyframes 하나를 나눠 쓴다. 파일 크기를 줄이기 위해서다.
- 점은 SMIL `animateMotion`과 `mpath`로 선 위를 옮긴다.
- 그림 아래에 단계 이름과 설명을 박자에 맞춰 바꿔 보인다. 설명이 하나도 없으면 단계 이름 한 줄 자리만 둔다.
- 조용한 선은 밝은 박자에만 보이는 keyframes를 따로 쓴다.
- 탭, 일시정지, 마우스 반응은 없다.

### 목록 쪽

- `--gallery`는 만든 HTML을 iframe으로 모은 `index.html`을 첫 그림의 폴더(`--out`이 있으면 그 폴더)에 쓴다.
- 다른 폴더의 그림은 목록 쪽 폴더에서 본 상대 경로로 잇는다.
- iframe 높이는 그림 쪽이 알린 본문 높이에 맞춘다. 카드는 줄에서 가장 긴 카드 높이로 늘이지 않는다. 짧은 그림 아래 빈 공간을 막기 위해서다.
- iframe은 브라우저 전체 화면을 쓸 수 있게 연다.
- 그림 설명은 원본에서 `#@`로 시작하지 않는 첫 주석 줄에서 가져온다.

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 점이 도착하는 도형의 카드는 도착할 때, 나머지 카드는 박자 시작에 바뀐다. | `test/build.test.js`의 `buildTimeline_card_changes_when_dot_arrives`, `buildTimeline_source_card_changes_at_beat_start` |
| 한 단계 안에서 지나간 선과 카드 내용이 남고 단계가 바뀌면 꺼진다. | `test/build.test.js`의 `buildTimeline_same_step_keeps_lit_edges_and_card` |
| 설명 길이만큼 멈추고 단계 끝에서 더 멈춘다. | `test/build.test.js`의 `buildTimeline_caption_change_dwells_by_length` |
| 조용한 선을 표시해 그린다. | `test/build.test.js`의 `build_quiet_edge_is_marked_and_rendered_hidden_class` |
| HTML과 움직이는 SVG를 만든다. | `test/build.test.js`의 `toHtml_and_toAnimatedSvg_include_player_and_motion` |
| 목록 쪽은 다른 폴더의 그림도 상대 경로로 잇는다. | `test/cli.test.js`의 `main_gallery_across_folders_links_each_figure` |
| 탭, 일시정지, 배속, 마우스 반응이 동작한다. | 브라우저에서 버튼을 눌러 상태가 바뀌는지 확인하는 테스트 |

## 단점

- 움직이는 SVG는 단계 수와 박자 수만큼 keyframes가 늘어 큰 흐름에서 파일이 커진다.
- 재생기 동작은 자동 테스트가 없어 브라우저 화면으로만 확인했다.

## 대안

- GIF 녹화: 크고 흐리며 멈출 수 없어 버렸다.
- 스크립트로 움직이는 SVG: GitHub가 이미지 안 스크립트를 막아 버렸다.
